# Технический план: продуктовая Academy

**Спека:** [spec.md](spec.md)  **Создан:** 2026-11-05

## Технологии

Существующие статические HTML/CSS/JS и Python HTTP-сервер. Каталог определяет роли, курсы, allow-listed Markdown и упражнения; сервер отдаёт только разрешённый контент после проверки роли.

## Архитектура

`вход по роли → каталог плиток → урок → текст первоисточника + блоки презентации + практика → отметка изучения`

## API

- `POST /api/access`: проверяет роль и пароль из окружения, выдаёт короткоживущий подписанный токен.
- `GET /api/course/document`: отдаёт разрешённый учебный Markdown после проверки токена.

## Ресурсы по блокам

| Блок | Модель | Скиллы | Агенты | Обоснование |
|---|---|---|---|---|
| Карта источников | fast/low | google-drive | — | извлечение структуры источников |
| UI и учебный поток | balanced/medium | frontend-design | — | существующий браузерный интерфейс |
| Ролевой API | frontier/high | security-review | — | защита материалов и паролей |
| Проверка | balanced/medium | verification-before-completion | — | маршрут, API и синтаксис |

## Риски

- В навигаторе есть секреты; строки после учебных данных не импортируются.
- У части материалов в таблице есть только названия; Academy использует соответствующие локальные паспорта и регламенты, а не выдумывает содержание.

## Проверка конституции

- [ ] Тексты берутся из allow-list первоисточников.
- [ ] Тесты остаются в текущей ролевой траектории.
- [ ] Пароли не попадают в клиентский код.
