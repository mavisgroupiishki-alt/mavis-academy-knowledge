# Технический план: ролевые рабочие пространства базы

**Спека:** [spec.md](spec.md)  **Создан:** 2026-11-10

## Архитектура

`effectiveAudience()` выбирает менеджера или эксперта: из аккаунта сотрудника либо из переключателя руководителя. Каталог фильтрует плитки по роли. Reader получает ролевую опорную карту из единого описания продукта и показывает пять смысловых блоков; источники группируются под этими блоками, а не делятся на технические типы документов.

## Изменения

1. Добавить `audience` в состояние интерфейса и переключатель руководителя.
2. Учитывать `roles` базовых и пользовательских плиток при построении каталога.
3. Заменить активный reader на рабочую структуру из пяти блоков.
4. Отделить менеджерские подсказки от экспертных: `03 SALES` показывать только менеджеру, `04 EXPERT` и профильные SOP — эксперту.
5. Добавить регрессионные тесты структуры и ролевого фильтра.

## Риски

- Старые пользовательские плитки могут не иметь роли; для них остаётся доступ обоим сотрудникам.
- Для плиток без отдельной ролевой карточки показывается общий безопасный каркас, а не придуманная нормативная конкретика.
