# Технический план: подробные экспертные маршруты и план стажировки

**Спека:** [spec.md](spec.md)
**Создан:** 2026-11-10

## Технологии

Существующие `manager-library.js`, `server.py`, `course-access.json` и встроенный API `/api/course/document`; без новой внешней зависимости.

## Архитектура

`COURSE → список паспортов → /api/course/document → выделение секции «Ход работы эксперта» → оформленные раскрывающиеся этапы в блоке «Ход работы»`.

Для стажёра `TRAINEE_COURSES + TRAINEE_DAYS` заменяются на прямую раскладку строк проверенной Google-таблицы. Тесты получают данные из role-specific конфигурации, а не из общего `course.check`.

## Схема данных

- `EXPERT_PASSPORT_SOURCES`: `courseId → paths[]`.
- `ROLE_CHECKS`: `courseId → {manager, expert}` с вопросом, вариантами, правильным ответом, порядком и кейсом.
- `TRAINEE_DAYS`: четыре дня и прямые ссылки на плитки из таблицы.

## Ресурсы по блокам

| Блок | Модель | Скиллы | Агенты | Обоснование |
|---|---|---|---|---|
| Извлечение паспортных этапов | balanced/medium | systematic-debugging | — | Нужна надёжная обработка существующего формата Markdown. |
| Карта стажировки | fast/low | google-sheets | — | Это точное перенесение уже проверенной таблицы. |
| Ролевые тесты и UI | balanced/medium | qa-testing-playwright | — | Нужна проверка разных клиентских сценариев. |

## Зависимости

Сначала подключаются недостающие паспортные пути и извлечение секций, затем ролевые тесты и стажёрская карта, после — тесты и браузерная проверка.

## Риски

- В отдельных паспортах таблица может быть пустой или состоять только из названий этапов. Такие карточки показываются как неполные, без выдумывания деталей.
- Удалённо сохранённая программа стажировки может переопределять кодовую базовую программу. Обновление выполняется только через существующий постоянный редактор или явную миграцию.

## Проверка конституции

- [ ] Паспортный текст не заменён общей выжимкой.
- [ ] Роли и тесты не смешаны.
- [ ] Стажёрский план повторяет источник.
