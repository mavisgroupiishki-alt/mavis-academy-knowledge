# Чек-лист переноса Mavis Knowledge на сервер

## Цель

Перенести рабочий vault и закрытый архив снимков так, чтобы база продолжала открываться, обновляться и восстанавливаться без утечки секретов или клиентских данных.

## До переноса

- [ ] Определить владельца сервера и техническую учётную запись синхронизации.
- [ ] Создать отдельные каталоги для vault и закрытого архива; не смешивать их.
- [ ] Настроить права: обычным пользователям — только vault по роли; архив — только технической учётной записи и согласованным администраторам.
- [ ] Создать новое защищённое хранилище секретов на сервере. Не копировать токены в заметки, Git или команды истории.
- [ ] Подготовить две независимые резервные копии, одна из них — вне сервера.
- [ ] Зафиксировать контрольные агрегаты выгрузок в [[06 BITRIX24/00 OVERVIEW/Bitrix24 — Статус импорта 2026-10-12|статусе Bitrix24]].

## Тестовый перенос

- [ ] Скопировать vault и архив в тестовый каталог, не переключая рабочую базу.
- [ ] Открыть тестовый vault в Obsidian и проверить главную страницу, поиск и вложения.
- [ ] Сверить количество и даты файлов с исходной копией.
- [ ] Выполнить одну read-only проверку Bitrix24 и убедиться, что секрет не появился в логах.
- [ ] Восстановить тестовую копию из резервной; зафиксировать результат.

## Переключение

- [ ] Приостановить ручные изменения на время финальной копии.
- [ ] Сделать свежую резервную копию локального vault.
- [ ] Скопировать финальную версию и повторить проверку открытия.
- [ ] Назначить серверную копию основной, локальную оставить как резервную на переходный период.
- [ ] Включить расписание read-only обновлений и уведомление только о сбоях.

## После переноса

- [ ] Проверить первое плановое обновление каждого источника.
- [ ] Проверить резервное восстановление не позднее чем через неделю.
- [ ] Согласовать, какие разделы доступны AI-агенту и кому он может отвечать.
- [ ] Отозвать старые технические доступы, если после тестов они больше не нужны.

## Условие готовности

Перенос считается завершённым только после успешного открытия vault, проверки первой синхронизации и успешного восстановления тестовой копии.
